# Macro6 更新日志

## v1.5 — 2026-08-26

- 修复单字符玩家 `L 已抵达。` 被漏识别的问题。
- 玩家状态掩码只保留与橙色名字同一文字行，避免横幅底边及背景灰色像素把“已抵达。”错误扩宽为“即将抵达。”。
- 为形状证据充分的单个大写 `L` 增加橙色字形几何保底；命中后直接输出 `L`，无需等待通用 OCR。
- 使用原始 ERROR 截图回放验证，结果为 `L / arrived`；回收箱过滤仍将该画面正确保留为玩家通知。

## v1.4 — 2026-08-25

- 将联机球后的固定“回收箱中存有物品。”系统横幅与玩家进出横幅分开识别。
- 回收箱横幅命中后不进入玩家名 OCR、不累计右侧横幅识别失败，也不再生成玩家通知 ERROR 截图或 error 日志。
- 回收箱文字/图标特征以内嵌压缩掩码保存在 watchdog 代码中，不依赖外部参考图片。
- 回收箱通知会结束当前视觉横幅分段，但不会增删玩家、改变房间状态或写入玩家事件。

## v1.3 — 2026-08-25

- RapidOCR/ONNX Runtime 固定为单核顺序推理，不再按默认设置占用全部物理核心。
- 玩家 OCR 工作线程在 Windows 中降为低于正常优先级，采集、控制、鼠标及前台软件优先获得 CPU 时间。
- Windows OCR 回退使用低优先级 PowerShell 子进程。
- 原始图和橙色柔化图已经识别出相同名字时，跳过第三套二值图推理，减少常规玩家名约三分之一的 ONNX 计算。
- OCR 精度投票和 FIFO 顺序保持不变；疑难名字在低资源模式下可能需要更长时间完成。

## v1.2 — 2026-08-25

- 玩家通知识别改为两级后台流水线，视频显示线程不再执行横幅文字分析或 OCR 预处理。
- 主线程只进行小区域联机球粗检测，并按 50ms 周期复制原始横幅裁剪。
- 后台分析线程负责橙色名字分割、固定状态识别、视觉指纹和横幅分段。
- 独立 OCR 线程负责生成原始、柔化、二值化三套玩家名输入并执行识别。
- OCR 较慢时，后续横幅仍由后台分析线程持续分段并按 FIFO 顺序等待，不阻塞 Watchdog 画面刷新。
- 玩家通知识别失败的完整原始画面截图改为后台请求、由下一次主循环按需复制，正常帧不再额外复制整幅画面。

## v1.1 — 2026-08-25

- 玩家横幅按视觉变化分段并进入异步 FIFO，避免较慢的玩家名 OCR 阻塞后续通知。
- 联机球持续显示时仍可依据名字及状态横幅变化区分不同通知；每个横幅段最多保留八帧。
- 暂时停用北京时间 05:00 自动重开；05:00 业务日计数、文件夹及日志归档规则保持不变。
- 玩家正常进出状态和玩家任务进度重新写入整体 `STAMP_日期.jsonl`。
- `PLAYERS_日期.jsonl` 只保留每轮 `room_reopen_summary` 汇总。
- 玩家日志删除 `recorded_at_utc`、`stamp_operational_date` 和 `day_boundary_beijing`。
- `recorded_at_beijing` 更名为 `record_time`，时间内容不再附带 `+08:00`。
- 玩家访问记录字段简化为 `incoming`、`arrived` 和 `ended`，删除重复的 `entry_time`。
