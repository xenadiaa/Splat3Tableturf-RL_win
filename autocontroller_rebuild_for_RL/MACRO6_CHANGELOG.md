# Macro6 更新日志

## v1.12 — 2026-08-28

- 修复多个 OCR 来源共同给出较短名字时压过单个完整候选的问题，例如已有 `rapid/orange` 识别到 `八彩彩`，最终却采用 `彩彩`。
- 三套 RapidOCR 图像变体现在全部执行，不再因前两个较短结果达成共识而提前跳过最后一个变体。
- 玩家名候选改为字符长度最高优先；存在 `八彩彩`、`彩彩`、`八` 时，只让最长的 `八彩彩` 进入来源共识、可信度比较和跨帧投票。
- `incomplete` 不再只代表“多字画面识别成单字”；只要本轮存在字符数更多的候选，所有较短候选都标记为不完整。
- 长度比较基于 Unicode 可见字符数量，不使用固定字符像素宽度；组合附加符、变体选择符和连接符不被错误计为独立字符。

## v1.11 — 2026-08-27

- 保留 v1.10 的完整玩家名优先规则；只要任一 OCR 路径取得完整候选，就不会使用残缺候选。
- 当全部 OCR 路径都被判为 `incomplete` 时，不再完全丢弃本次玩家通知；按字符数最长、独立 OCR 来源共识最多、可信度最高的顺序选择兜底名字。
- `incomplete` 兜底结果仍须通过原有的跨帧两票确认后才能更新房间，不会根据单帧残缺识别立即增删玩家。
- 终端 OCR 候选日志新增 `incomplete-fallback=...`，明确标注本次房间更新使用了残缺兜底。

## v1.10 — 2026-08-27

- 修复完整双字/多字玩家名被通用 OCR 高置信度截成首字后提前通过的问题，例如 `来须` 被记录为 `来`。
- 完整姓名裁剪和可变字符宽度保持不变；新增规则仅以原始橙色墨迹整体宽高判断画面是否明显存在多个字形，不按固定单字宽度切割。
- 当画面明显为多字形时，单字符 OCR 结果标记为 `incomplete`，不能参与候选胜出或触发提前结束；继续尝试二值变体及 Windows 中/英文 OCR。
- 真正单字名与 v1.5 的大写 `L` 几何保底保持有效；无法取得完整候选时宁可继续重试，不再把明显残缺的首字写入房间状态。
- 终端会保留被拒绝短候选的 OCR 来源和 `incomplete` 标记，便于后续核验。

## v1.9 — 2026-08-26

- 玩家横幅在主视频线程生成原始裁剪时立即分配单调递增的 `capture_sequence`、采集时间和房间代次。
- 原始顺序元数据贯穿后台分析、视觉分段、OCR队列、两帧投票及房间状态应用；不再以OCR完成时间代表事件顺序。
- 增加硬顺序门：准备应用的事件若不晚于最后已应用的原图序号，直接丢弃，不允许旧OCR结果在稍后插入。
- 每个玩家记录最后事件序号和离开标记；离开后迟到的“已抵达”不会重新加入，必须先收到原图序号更新的“即将抵达”才能开始新访问。
- 新CODE清空玩家生命周期序号和离开标记；新一轮首次直接出现“已抵达”仍可正常接收。
- 玩家状态JSON新增 `ocr_player_name`、`capture_sequence`、`capture_time`、`segment_id` 和 `processing_delay_ms`，便于核验原图顺序与OCR延迟。
- 回归中修正 `capture_20260824_170628_353544_00003` 的既有状态误判：淡出灰色尾迹使宽度变长时，明显更优的“已抵达”固定模板可以覆盖宽度规则。

## v1.8 — 2026-08-26

- 修复离开横幅把 `百變怪` 截短识别为 `百`、把 `哈哈` 截短识别为 `哈` 后无法移除原玩家的问题。
- `left` 事件优先在当前房间玩家中进行唯一包含关系匹配；单字截断仅在唯一候选时归并，避免多个相同首字玩家之间误删。
- 非包含型 OCR 小误差可在相似度不低于 0.60 且领先第二候选至少 0.15 时归并；原有 0.78 通用阈值保持不变。
- 自动纠正时终端输出原始 OCR 名与最终房间名；JSON 玩家状态记录使用纠正后的完整名字。
- 单字符 `L` 几何保底规则未扩展到中文字符，本次问题不是 v1.5 主动单字识别造成的。

## v1.7 — 2026-08-26

- 将五分钟手柄保活设为 F12 操作锁的唯一后台输入例外。
- F12 锁定期间仍按实际手柄活动计算 300 秒；到期发送一次 DPAD 上、下，防止等待 `POK_SAV_STATE` 时画面变暗。
- F12 继续禁止全部人工键盘操作，不会放行宏触发、中断、退出、截图或普通手动控制键。

## v1.6 — 2026-08-26

- 按 Nintendo Switch 官方“减少屏幕灼伤”五分钟无操作变暗时间，新增 300 秒全局手柄输入空闲计时器。
- 宏动作和所有有效的正常手动控制按键都会重置空闲计时；F10、统计键及无效键不冒充手柄活动。
- 连续 300 秒没有任何实际手柄按下时发送 `DPAD上50ms → 归中100ms → DPAD下50ms → 归中`，随后重新计时。
- 等待 `POK_SAV_STATE` 小对号、视觉状态等待、宏内长等待、P 暂停和 Macro6 待机状态均受同一保活计时器保护。
- 此版本最初在 F12 操作锁期间禁止保活；该规则已由 v1.7 调整为允许保活。

## v1.5 — 2026-08-26

- 修复单字符玩家 `L 已抵达。` 被漏识别的问题。
- 玩家状态掩码只保留与橙色名字同一文字行，避免横幅底边及背景灰色像素把“已抵达。”错误扩宽为“即将抵达。”。
- 为形状证据充分的单个大写 `L` 增加橙色字形几何保底；命中后直接输出 `L`，无需等待通用 OCR。
- 使用原始 ERROR 截图回放验证，结果为 `L / arrived`；回收箱过滤仍将该画面正确保留为玩家通知。

## v1.4 — 2026-08-25

- 将联机球后的固定“回收箱中存有物品。”系统横幅与玩家进出横幅分开识别。
- 回收箱横幅命中后不进入玩家名 OCR、不累计右侧横幅识别失败，也不再生成玩家通知 ERROR 截图或 error 日志。
- 回收箱文字/图标特征以内嵌压缩掩码保存在 watchdog 代码中，不依赖外部参考图片。
- 回收箱通知会结束当前视觉横幅分段，但不会增删玩家、改变房间状态或写入玩家事件。

## v1.3 — 2026-08-25

- RapidOCR/ONNX Runtime 固定为单核顺序推理，不再按默认设置占用全部物理核心。
- 玩家 OCR 工作线程在 Windows 中降为低于正常优先级，采集、控制、鼠标及前台软件优先获得 CPU 时间。
- Windows OCR 回退使用低优先级 PowerShell 子进程。
- 原始图和橙色柔化图已经识别出相同名字时，跳过第三套二值图推理，减少常规玩家名约三分之一的 ONNX 计算。
- OCR 精度投票和 FIFO 顺序保持不变；疑难名字在低资源模式下可能需要更长时间完成。

## v1.2 — 2026-08-25

- 玩家通知识别改为两级后台流水线，视频显示线程不再执行横幅文字分析或 OCR 预处理。
- 主线程只进行小区域联机球粗检测，并按 50ms 周期复制原始横幅裁剪。
- 后台分析线程负责橙色名字分割、固定状态识别、视觉指纹和横幅分段。
- 独立 OCR 线程负责生成原始、柔化、二值化三套玩家名输入并执行识别。
- OCR 较慢时，后续横幅仍由后台分析线程持续分段并按 FIFO 顺序等待，不阻塞 Watchdog 画面刷新。
- 玩家通知识别失败的完整原始画面截图改为后台请求、由下一次主循环按需复制，正常帧不再额外复制整幅画面。

## v1.1 — 2026-08-25

- 玩家横幅按视觉变化分段并进入异步 FIFO，避免较慢的玩家名 OCR 阻塞后续通知。
- 联机球持续显示时仍可依据名字及状态横幅变化区分不同通知；每个横幅段最多保留八帧。
- 暂时停用北京时间 05:00 自动重开；05:00 业务日计数、文件夹及日志归档规则保持不变。
- 玩家正常进出状态和玩家任务进度重新写入整体 `STAMP_日期.jsonl`。
- `PLAYERS_日期.jsonl` 只保留每轮 `room_reopen_summary` 汇总。
- 玩家日志删除 `recorded_at_utc`、`stamp_operational_date` 和 `day_boundary_beijing`。
- `recorded_at_beijing` 更名为 `record_time`，时间内容不再附带 `+08:00`。
- 玩家访问记录字段简化为 `incoming`、`arrived` 和 `ended`，删除重复的 `entry_time`。
